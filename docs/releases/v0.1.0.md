First release.

Compile an XTCE definition into a `no_std` Rust **encoder** — and decoder — for the spacecraft
side. Telemetry going down, telecommands coming up.

## Why this exists

Ground software reads packets, and the public XTCE tooling reflects that: parsers, decoders,
displays. Flight software writes them, on a part with no heap, no operating system and a hard
rule against a code path that can panic. The generators that produce that half are written
inside the companies that fly, and stay there.

## What it is tested against

42 tests, and a gate that is not a test: `./scripts/check-no-panic.sh` builds the generated
code for `thumbv7em-none-eabihf` and proves no panic path exists in it — not that none was
hit, that none is reachable. No `unsafe`, no heap, no formatting machinery linked in.

The generated encoder is checked against `xtce-decode` on 256 seeded packets per container:
what this writes, the ground half reads back as the values that went in. All 63 488 finite
binary16 encodings are checked both ways, because no mission definition in reach has a 16-bit
float and nothing else would catch an error there.

## Scope

It compiles a narrower subset than the interpreter and refuses anything else by name rather
than falling back silently. Pinned to `xtce-codegen` by revision.
