A definition shape that generated a decoder rejecting every packet is refused instead.

## What was wrong

`abstract` defaults to **false** in XTCE. So a base `SequenceContainer` that nobody marked —
the ordinary CCSDS primary-header shape, which is most definitions — was emitted as a concrete
container, and a concrete container with no restriction criteria has `true` for the body of its
generated `matches`.

The module-level `decode` counts how many containers match and refuses a packet that matches
more than one. Every packet therefore matched the base *and* its own child, and every packet
came back `DecodeError::Ambiguous`. The generator said nothing, and the place that would have
found out is the spacecraft.

It is refused at generation time now, naming the container and giving both ways out:

```console
$ xtce-flight generate mission.xml -o telemetry.rs
error: cannot compile <SequenceContainer> in FlightPacket: this container has no restriction
criteria, so it matches every packet long enough to hold it; beside the other containers
generated here that makes every packet ambiguous. Mark it abstract="true" if other containers
inherit from it, or give it criteria that select it
```

Narrow on purpose: only when the definition has more than one container. A lone concrete
container with no criteria *is* the whole definition and still generates.
